## Task 1: Reducer for the v2 event vocabulary (fixture-driven)

Files: `src/book/events.ts` (rewrite the event mapping; keep `applyEvent(book, event)` as the entry point), `src/book/model.ts`, `src/book/diff.ts`, `src/book/tools.ts`, `src/book/transcript.ts` (new: v2 messages → chapter), `src/book/events.test.ts`, `src/book/transcript.test.ts`, test fixtures copied into `src/book/__fixtures__/` from the recorded captures (`fixture-edit.sse`, `fixture-ask.sse`, `aux-question.sse`, `aux-reject.sse`, `aux-interrupt.sse`, `fixture-edit-messages.json`, `fixture-edit-diff.json`; strip nothing, they are small).

The event frame is `{id, created?, type, location?, data, durable?}` (see notes §7). `applyEvent` takes the frame as-is (`type` + `data`), never `properties`. The internal id scheme replaces part ids: text block id `${assistantMessageID}:t${ordinal}`, reasoning is dropped, tool id = the tool call `id`, user ink block id = the user message id (from the prompt response or transcript), optimistic local blocks `local-…` are adopted by text match as today.

1. Chapter shells: `session.created` (filter by `location.directory` vs `book.directory`), `session.renamed` → title (`isUntitled` rules stay), `session.deleted`.
2. Busy: `session.execution.started` → `busy: true`, `error: undefined`; `session.execution.succeeded` → idle, close pending margin notes; `.failed {error}` → idle + `error: error.message` (or a sentence per `error.type`); `.interrupted {reason}` → idle, no error for `reason: "user"`, notice "The press was interrupted." otherwise. `session.retry.scheduled {attempt, error}` → `chapter.notice = "Trying again (attempt N)…"`, cleared on the next step.
3. Text: `session.text.started {assistantMessageID, ordinal}` creates an empty prose block (marginal if a margin note is pending, as today); `session.text.delta` appends; `session.text.ended {text}` sets the full text (never shorter). `session.reasoning.*` ignored. `session.step.started` records `assistantMessageID → turn user message id` (the last ink block's id) in `chapter.turns` so plates can name the turn.
4. Tools: `session.tool.called {id, name, input}` → footnote (status running) via `footnoteSentence`; map v2 inputs: `read {path}`, `edit {path, oldString, newString}`, `write {path, content}`, `bash/shell {command}`, `glob/grep {pattern, path?}`, `question`, `webfetch {url}`, `websearch {query}`; `tools.ts` reads `path` as well as `filePath`; there is no `title` in v2, derive it. `session.tool.success {id, content[], metadata}` → completed; output = joined `content[].text`; for edit/write, `metadata.files[]` (`{file, patch, status, additions, deletions}`) opens/updates a plate whose lines come from `parsePatch(patch)` (new in `diff.ts`: unified diff with `Index:`/`diff --git` headers, one or more `@@` hunks, correct old/new numbering, `\ No newline` skipped, capped at 42 lines with a trailing "…" context line when truncated). `session.tool.failed {id, error}` → footnote error text; `error.type === "aborted"` or `"permission.rejected"` reads "declined" not "failed". `session.tool.input.*` and `session.tool.progress` ignored.
5. Diff refresh: `session.step.ended {assistantMessageID, files[]}` with non-empty `files` sets `chapter.diffStale = true` (the hook fetches `GET /api/session/{id}/diff` and dispatches an internal `folio.diff {sessionID, diff}` frame). `folio.diff` upserts plates by file (id `diff-<file>`), lines from `parsePatch`, caption per status ("New file …", "Removed …", "The change in …"), keeps `status`/`folded` of an existing plate, and records `turnMessageId` = the current turn's user message id on new plates.
6. Permissions: `permission.asked {id, action, resources[], metadata?.files[], source?}` → `chapter.asks` entry `{id, permission: action, patterns: resources, title: "May I edit src/greet.ts?", patch?: first metadata.files[].patch}`; `permission.replied {requestID}` removes it. Verb map: edit→"edit", read→"read", shell→"run", `*`→"act on".
7. Forms: `form.created {form}` → `chapter.forms: Form[]` with `{id, title, fields:[{key, title, description?, type, options?:[{value,label,description?}], custom?, min?, max?}]}`; `form.replied`/`form.cancelled` remove it.
8. Unknown event types and unknown content/tool shapes are ignored (`applyEvent` returns the same book object, so React does not re-render).
9. `transcript.ts`: `chapterFromMessages(chapter, messages)` builds blocks/footnotes/plates from `GET /api/session/{id}/message?order=asc` (user → ink block; assistant.content: text → prose blocks by ordinal, tool → footnote + plate via `metadata.files`; `idle` messages skipped; the last assistant `error` → chapter error when the session is not running). Reuse the same helpers as the event path so both agree.
10. Tests: drive `applyEvent` with every frame of `fixture-edit.sse` (parsed with the real `pushSse`) and assert: one ink block with the prompt text, three footnotes (read, edit, …) in order, the edit footnote completed with a plate whose lines contain `+export function farewell`, exactly one prose block with the final explanation, no reasoning text anywhere, `busy` false at the end, `diffStale` true after the step with files. Same for `fixture-ask.sse` (an ask appears with the patch, then disappears after `permission.replied`), `aux-question.sse` (a form with options appears), `aux-reject.sse` (tool declined wording, turn continues), `aux-interrupt.sse` (idle, no error). `transcript.test.ts` builds the chapter from `fixture-edit-messages.json` and asserts the same block/footnote/plate counts as the event path. `parsePatch` tests: the fixture patch, a two-hunk patch, added file, deleted file, truncation.

## Task 2: Stable pagination while streaming

Files: `src/book/paginate.ts`, `src/book/wrap.ts`, `src/state/useFolio.ts`, `src/book/layout.test.ts`.

Goal: while the press streams, already-laid lines and pages never move; only the tail grows. No visible layout jumps.

1. Make `paginateChapter` incremental: memoize per chapter on `(block ids+texts prefix, footnotes, scale)`. Keep a cache `Map<chapterId, { blocksKey: string[], pages: LaidPage[], carry: {…} }>` so that when only the last block's text grows (or a new block is appended), lines for earlier blocks are reused verbatim and only the last block is re-wrapped. Simplest acceptable design: lay out blocks one at a time with `wrapParagraph`, cache wrapped lines per `(blockId, text, marks)`; the page-fill pass over cached lines is cheap. Then prove stability with `committedPrefix` in tests: for a chapter whose last block grows by word increments, `committedPrefix(before, after) >= after.length - 1` at every step and every line that is not the last line of the last paragraph is identical.
2. Greedy wrap is prefix-stable only if the last line is allowed to change. Guard: footnote marks that attach to the last block anchor at `offset = text.length` at creation (see `anchorFor`), which can move when text grows. Change `anchorFor` to anchor a footnote at the end of the last **completed sentence** of the last non-marginal block at the time the tool part arrives, and keep that offset fixed (store it; do not recompute). If the block has no text, anchor at `pending` and let the next text part adopt it (existing behavior).
3. Coalesce deltas: in `useFolio`, batch SSE events with `requestAnimationFrame` (or a 16 ms timer in non-browser) so many `message.part.delta` events per frame cause one `setBook`. Keep ordering.
4. The auto page turn (`prevSpreads` effect) must fire only when the user is on the last spread of the chapter being written and the new page belongs to that chapter.
5. Tests: wrapped-line stability under word-by-word growth; a footnote anchor does not move once set; delta batching reduces N events to 1 state update (unit test on a pure `coalesce` helper).
